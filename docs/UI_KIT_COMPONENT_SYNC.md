## Hover у FAQ
Hover 2 управляется наведением на весь элемент details: зелёная рамка и подчёркнутый вопрос одновременно. Это работает на границе компонента и над раскрытым ответом. На главной раскрытие текста кнопки «Открыть/Закрыть» тоже привязано к целому details. Взаимодействие с клавиатуры и нативное поведение details не изменены.

## Input Active и исчезновение Glass Effect
В исходных Figma input_Text и input_Phone Active effects = []; только зелёный stroke 1.5px. Ранее в Astro были добавлены outline 3px black и box-shadow с белым ореолом 7px. Они удалены из TextField.astro. Салатовая рамка остаётся видимым индикатором фокуса. Mobile высота 50px, текст 14px.

## Иллюстрации и компоненты Mobile
Сохранены девять оригинальных SVG, экспортированных без перерисовки из Figma: шесть для illustration_Formats и три для illustration_For who?. Компоненты PrintFormatCard и AudienceCard используют picture/source для Mobile-вариантов при ширине до 58rem; Desktop по-прежнему использует ранее согласованные файлы. Названия исходных компонентов зафиксированы через data-illustration-group и документацию; публичные пути старых SVG не переименовывались, чтобы не нарушать существующие страницы.

Важное уточнение по двум одноимённым компонентам: Figma содержит ДВА набора block_Услуга. Node 51:1626 — карточка настоящей услуги (только Desktop M/L, Default/Hover). Node 183:7337 — карточка «Для себя / Для команды / Для организации», у которой Mobile 340×344. Реализован именно подтверждённый Mobile для второго набора. У illustration_Services (51:1637) нет варианта Device=Mobile; искусственно создаваемых новых мобильных иллюстраций не добавлено.

## Границы и проверки
Playwright: hover FAQ с наведением на границу и ответ; отсутствие дополнительного контура input Active; Desktop/Mobile геометрия компонентов; наличие девяти SVG и соответствие currentSrc; совместимость старых страниц. Не делается полная мобильная приёмка всех страниц, не меняются master, hoster.by, политика безопасности или интеграции.
