## Обязательная приёмка библиотеки после установки

1. `npm run check`, затем `npm run build:kit`.
2. `npm run dev`; открыть `/__ui/` на выданном локальном адресе.
3. Дождаться загрузки Inter/JetBrains Mono и всех изображений; проверить Network и Console.
4. Сравнить размеры/цвета/шрифты с узлами из COMPONENT_MAP, отдельно на светлом и тёмном фоне.
5. Клавиатурой пройти ссылки, кнопки, поля, checkbox услуг и FAQ. Проверить disabled и фокус.
6. Вставить и отредактировать телефон, выделить середину номера, удалить и повторить ввод.
7. Проверить независимость экземпляров, перенос длинного текста, zoom 200% и reduced motion.
8. Проверить ширины 320, 360, 390, 430, 768, 1024, 1366, 1470, 1920;
   для текущего технического breakpoint 768 проверить 767/768/769. Он ещё не утверждён для страниц.
9. После прохождения базовой библиотеки добавить оставшиеся составные компоненты и проверить их.

Production-сборка намеренно блокируется `scripts/release-gate.mjs` до закрытия пунктов
в `docs/release-status.json`. Этот файл отражает проверки, а не заменяет их.

## Облачные проверки development

Добавлен workflow `development-check.yml`. При отсутствии package-lock он один раз создаёт и сохраняет lock в development без изменения других файлов. Далее используются npm ci, Astro check, сборка витрины и Playwright в Chromium/Firefox/WebKit.
Проверяются 11 ширин (включая 767/768/769), переполнение, локальные шрифты, ресурсы/Console, семантика полей, независимость FAQ/checkbox, клавиатура, редактирование телефона, disabled/busy, размеры при hover, 200% размер текста и reduced motion.
Это эмуляция в CI, не проверка на физических телефонах и не визуальная приёмка по Figma. Скриншоты сохраняются для отдельного просмотра. Workflow не содержит публикации; dist-kit и отчёты — временные Actions-артефакты.
Результат первого запуска ещё не зафиксирован; наличие тестов не означает их прохождение.
