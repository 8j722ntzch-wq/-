## Архитектура

Статический Astro; HTML-компоненты и CSS, без React/Vue/Tailwind.
Токены → UI → составные блоки → секции → страницы. Сейчас сделан только первый слой UI.
Страница `/__ui/` внедряется интеграцией только для dev или явной тестовой сборки.
Исходник витрины лежит вне `src/pages`. `dist-kit` не является production-артефактом.

Технологический выбор: Astro 7.4.12, @astrojs/check 0.9.12; версии проверены по официальным источникам.
https://docs.astro.build/en/upgrade-astro/
https://www.npmjs.com/package/@astrojs/check
Node: минимум 22.23.4; локально обнаружен 26.13.0. Для CI планируется поддерживаемая LTS-линия.
Зависимости ещё не установлены; lock-файл отсутствует, сборка и лицензии установленных пакетов не проверены.

## Порядок продолжения

1. Выполнять установку, сборку и проверки в GitHub Actions из development; пользовательский компьютер для этого не требуется.
2. Установить зависимости, получить lock-файл; сверить лицензии шрифтов Inter/JetBrains Mono.
3. Экспортировать оригинальные иконки/логотип/фото/иллюстрации; проверить тип, размеры, пропорции и соответствие узлам.
4. Пройти check, собрать UI Kit и проверить восемь базовых компонентов в браузере.
5. Доработать иконки, checkbox, формы, dialog, Header/Footer, карточки, таблицы, галереи и слайдеры; повторить браузерную проверку.
6. Получить подробный design context каждой секции 12 экранов, включая свойства/прототип; текущая инвентаризация это не заменяет.
7. Собрать страницы и проверить адаптивность на 320/360/390/430/768/1024/1366/1470/1920 и вокруг breakpoint.
8. Согласовать и подключить серверный контракт заявки; проверить подтверждённую доставку нужному получателю.
9. Провести security/SEO/performance/release review. Только затем подготовить PR development → master для команды на выпуск.

Исследование не объявляется полным: не изучены все секции в высокой детализации,
прототипные связи, точные свойства всех ресурсов и полный набор состояний составных компонентов.
