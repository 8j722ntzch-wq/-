# Закрытый staging-сайт baltmotors.by

Режим предназначен только для показа мастерской заказчику. Код реализован в `development`, **master и hoster.by пока не обновляются**.

## Архитектура

- `/preview-login/` — адаптивная Astro-страница из существующих `TextField` и `Button`; Mobile 390px и Desktop. Фирменные Inter, JetBrains Mono, синий и салатовый.
- `server/preview/.htaccess` направляет ВСЕ запросы (HTML, JS/CSS, изображения, PDF) через `_preview/gate.php`.
- Незалогиненный посетитель попадает на форму входа. HTML страницы входа собирается с встроенными CSS/шрифтами; публичных исключений для ассетов нет.
- `_preview/auth.php` проверяет логин, пароль bcrypt, CSRF и лимит попыток; выдаёт Secure/HttpOnly/SameSite cookie, авторизация действительна до 12 часов.
- Уже существующий `/api/submit.php` для Telegram разрешён только авторизованным посетителям; его проверка Origin и доставка сохраняются.
- `noindex, nofollow` есть в метатегах; сервер добавляет `X-Robots-Tag: noindex, nofollow, noarchive` для HTML и PDF; robots.txt запрещает обход.
- Секрет не находится в публичном GitHub и не попадает в HTML/JS.

## Создание пароля на hoster.by

Ранее согласован корень сайта `/www/baltmotors.by`, PHP LSAPI 8.4.27. В панели hoster.by **перед публикацией** включить HTTPS и перенаправление HTTP → HTTPS.

1. Через терминал проверить возможность создания файла вне корня сайта — в каталоге `/www`. Файл `/www/.masterskaya-preview-auth.php` НЕ должен быть доступен по URL.
2. Получить bcrypt-хеш пароля, введя следующую команду (пароль передаётся через STDIN, не в аргументах команды и не в истории shell):
   ```sh
   php -r '$p = rtrim(fgets(STDIN), "\r\n"); echo password_hash($p, PASSWORD_BCRYPT, ["cost" => 12]), PHP_EOL;'
   ```
   После запуска вставить пароль из нашего чата и нажать Enter. Результат начинается с `$2y$`.
3. Создать приватный файл `/www/.masterskaya-preview-auth.php` со следующим содержимым (вставить полученный хеш вместо плейсхолдера):
   ```php
   <?php
   return [
       'username' => 'preview',
       'password_hash' => 'СЮДА_ПОЛНЫЙ_BCRYPT_ХЕШ',
   ];
   ```
   Установить минимально необходимые права, по возможности `chmod 600 /www/.masterskaya-preview-auth.php`.
4. Проверить, что PHP на сайте может прочитать этот файл. При его отсутствии или ошибке содержимого серверная защита возвращает HTTP **503** и не выдаёт страницы.
5. Если каталог `/www` недоступен, НЕ помещать пароль или конфиг в публичную папку. Сначала согласовать с поддержкой hoster.by правильное приватное расположение.

## Сборка для демонстрации

```sh
npm ci
npm run check
npm run build:preview
```

`dist-preview/` содержит защищённый SSG, все компоненты и `_preview/*.php` плюс корневой `.htaccess`. Файл `_preview/login.html` создаётся с полностью встроенными стилями и шрифтами. **Нельзя раздавать `dist-preview` обычным статическим веб-сервером:** PHP и действующие rewrite-правила обязательны.

Основной `npm run build` по-прежнему блокируется release gate. Автоматический SFTP-деплой и публикация `master` пока не включены.

## Жёсткая приёмка перед публикацией

После настройки HTTPS и закрытой пробной публикации содержимого `dist-preview/` (включая скрытый файл `.htaccess`) проверить в инкогнито:

1. `/`, `/portfolio/`, `/services/repair/` без куки **не** показывают HTML сайта, а перенаправляют на HTTPS `/preview-login/`.
2. Прямые `/assets/figma/portfolio-ruckit.jpg`, `/_astro/*.css`, `/documents/personal-data-policy.pdf` без куки НЕ возвращают открытый контент (HTTP 200).
3. Страница входа показывается на Mobile и Desktop, её поля/кнопка работают, неправильные данные не дают доступ, правильные — открывают сайт.
4. Авторизованному посетителю доступны вложенные страницы, изображения и PDF, а скрытые файлы `/_preview/*.php` и `/.htaccess` не доступны.
5. Все ответы содержат `X-Robots-Tag`, HTTP перенаправляется на HTTPS. Запрос к Telegram API без авторизации получает 401.
6. Если `.htaccess` игнорируется (например, статические файлы отдаются Nginx напрямую), **немедленно остановить публикацию** и запросить серверную блокировку в поддержке hoster.by. Падение тестов или открытый URL изображения = сайт не защищён.

Проверки `.github/workflows/preview-security-check.yml` выполняют `astro check`, отдельную сборку, проверку синтаксиса PHP, тестовые запросы без настоящих секретов и браузерную проверку формы входа. Реальная защита hoster.by всё равно требует внешней проверки.

Репозиторий GitHub публичный: пароль закрывает только сайт, а не исходники. Если нужно скрывать исходный код, репозиторий следует сделать приватным.
