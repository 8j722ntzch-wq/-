# Мастерская — разработка Astro-сайта

Репозиторий сайта **baltmotors.by**.

## Текущий этап

Собрана библиотека базовых и составных Astro-компонентов по Figma: хедер, футер, карточки, формы, окна, прайс, полные стили и шесть новых иллюстраций.
Страницы сайта ещё не собраны: переход к ним возможен после браузерной приёмки библиотеки.
Production не готов; автоматическая публикация не включена.

Сборка расширенной витрины проходит. Результаты текущих проверок — в docs/VERIFICATION.md. Мобильная приёмка отложена до готовности макета.

## Рабочий процесс

Изменения сохраняются в `development`. Установка, сборка и браузерные проверки выполняются в GitHub Actions (`development-check.yml`). Lock-файл сохранён. Workflow использует `npm ci` и имеет только права чтения репозитория.
Локальный Astro уже запущен пользователем; витрина открыта в ChatGPT: http://127.0.0.1:4324/__ui/ .
По обновлённому заданию включены все шесть иллюстраций из набора 168:6290. Figma не изменяется. Узкие экраны сейчас не тестируются.

## Команды для среды разработки

Node.js 22.23.4 (зафиксирован в .nvmrc); установка по package-lock.json — `npm ci`.
Полный набор зависимостей и браузерные проверки воспроизводятся в облачном workflow.

```sh
npm ci
npm run check
npm run dev
```

Открыть `/__ui/` на локальном адресе Astro. Витрина работает только в dev либо в специальной
тестовой сборке `npm run build:kit`. Результат `dist-kit/` не публиковать.
`npm run build` блокируется до выполнения критериев из `docs/release-status.json`.
Для обычного production-режима `/__ui/` не включается в маршруты.
Секреты и переменные Telegram на этом этапе не нужны; endpoint формы ещё не согласован.

## Ветки
- `development` — разработка и проверка изменений.
- `master` — стабильная версия для публикации на сайте.

## Выпуск обновлений
1. Вносить изменения в `development`.
2. Проверять сборку и работу сайта.
3. Создавать Pull Request: `development` → `master`.
4. После проверки объединять изменения.
5. Публикация из `master` на hoster.by будет настроена через GitHub Actions и SFTP после проверки доступа к серверу и структуры проекта.

Не хранить пароли, приватные ключи или другие секреты в репозитории.
