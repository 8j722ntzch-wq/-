# Мастерская / Печатка — сайт на Astro

Репозиторий сайта мастерской по ремонту, подгонке и персонализации одежды. Целевой домен — **baltmotors.by**, хостинг — **hoster.by**, город проекта — **Витебск**. Домен не следует считать названием бренда.

**Стадия на 19.11.2026:** Desktop-вёрстка основных экранов реализована; часть Mobile-экранов реализована; продолжаются визуальная приёмка, адаптация, согласование контента и подключение заявок. **Production не готов и не опубликован из этого репозитория.**

**Итого: 12 Desktop-экранов и 6 Mobile-версий в коде.** Это статус реализации, не финальная приёмка: тексты, цены, контакты, кейсы и визуальная точность ещё требуют проверки. Шесть карточек портфолио используют всего два уникальных проекта; повторения не являются шестью подтверждёнными заказами.

PDF политики доступен по `/documents/personal-data-policy.pdf`; его юридическая редакция требует отдельной сверки.

## Архитектура

- **Astro 7.4.12**, статическая генерация (SSG), TypeScript и CSS без React/Vue/Tailwind.
- **Node.js 22.23.4** зафиксирован в `.nvmrc`; установка воспроизводится через `package-lock.json`.
- Компоненты: `src/components/ui` (кнопки, поля, checkbox и др.), `cards`, `blocks`, `dialogs`, `forms`, `portfolio`; общие токены — `src/styles`.
- Данные страниц и локальные ресурсы Figma — `src/data` и `public/assets/figma`. Шрифты — Inter и JetBrains Mono; лицензии сохранены.
- Галерея компонентов `/__ui/` доступна **только** в режиме разработки или тестовой сборке `build:kit`; в обычный production не входит.
- Реальные макеты — [Figma «Сайт печатки», раздел «Проект»](https://www.figma.com/design/Zt53vIZnK6OY4tEvSRBN9C/?node-id=1-6). Figma не изменяется автоматически.

## Формы и Telegram

Обе формы (встроенная и в диалоге) проверяют имя, телефон, услугу и согласие; кнопки со страницы передают контекст заявки. **Реальной серверной отправки пока нет**: в `ConsultationForm.astro` показывается сообщение о предпросмотре; успех доставки в Telegram не имитируется.

Для запуска требуется отдельный обработчик на hoster.by, новый выделенный Telegram-бот и группа именно этого проекта, проверенный контракт запроса, серверное хранение секретов, защита от повторов и подтверждение ответа Telegram. Не переносить токены, получателей или настройки Revolis.Мото. См. [FORMS.md](docs/FORMS.md).

## Проверки

GitHub Actions [Development component checks](.github/workflows/development-check.yml) автоматически выполняется при push в `development` и PR в эту ветку:

1. `npm ci`, `npm run check`, `npm run build:kit`;
2. Playwright UI-тесты в Chromium, Firefox и WebKit, включая мобильные макеты 390 px;
3. проверку известных и новых предупреждений зависимостей (см. [SECURITY_AUDIT.md](docs/SECURITY_AUDIT.md)).

**Актуальный результат CI проверять на [странице Actions](https://github.com/8j722ntzch-wq/-/actions/workflows/development-check.yml)**: старые числа успешных тестов из исторических документов не означают, что прошёл последний коммит. Матрица проверок и ограничения описаны в [VERIFICATION.md](docs/VERIFICATION.md).

Для локальной среды или одноразовой среды предпросмотра:

~~~sh
npm ci
npm run check
npm run dev
# в другом терминале при запущенном dev:
npm run test:ui
~~~

Открыть локальный адрес Astro и `/__ui/`. Для проверочной статической сборки использовать `npm run build:kit` (каталог `dist-kit/` **нельзя** публиковать).

## Релиз и инфраструктура

- `development` — разработка. `master` — ветка для будущей стабильной публикации. Не переносить изменения в `master` без отдельного решения и полной приёмки.
- `npm run build` намеренно блокируется [release gate](docs/release-status.json), пока не завершены компоненты, Mobile, контент, доставка заявок, безопасность и production review. Метатег `noindex, nofollow` сохраняется до согласованного релиза.
- Проверка SFTP-входа и чтения каталога hoster.by ранее была успешной. Это **не** подтверждает разрешение записи, правильный каталог домена, HTTPS или развёртывание. Автоматический workflow деплоя ещё не подключён. См. [HOSTER_SETUP.md](docs/HOSTER_SETUP.md).
- После готовности: проверить контент и юридические документы, закрыть функциональные и UI-тесты, проверить конфигурацию публикации, согласовать PR `development` → `master`, только затем включать SFTP-деплой и проверять опубликованный сайт.
